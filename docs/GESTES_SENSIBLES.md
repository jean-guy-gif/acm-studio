# Les écritures en base et ce qui les prouve

Inventaire fait le 12/10/2026 (mission 100). Une ligne par action serveur qui écrit en base.
À tenir à jour quand une action s'ajoute.

**Les preuves, par ordre de force**

- **Base (CI)** : un test SQL de `supabase/tests/`, joué à chaque push sur une base locale, dans le
  rôle du navigateur. Il prouve la règle là où elle s'applique.
- **Action** : un test qui appelle l'action elle-même avec un client factice
  (`src/features/sensitive-actions.test.ts`, `search-budget-action.test.ts`,
  `src/lib/app-errors/record.test.ts`). Il prouve les gardes et ce qui est écrit.
- **Service** : un test d'une fonction pure que l'action utilise. Il ne prouve **ni** le garde
  **ni** l'écriture.
- **e2e** : le parcours à l'écran, lancé à la main, jamais dans la CI.

Deux tests SQL couvrent **toutes** les tables d'un coup, et valent donc pour chaque ligne
ci-dessous : `agency_isolation_all_tables.sql` (un membre d'une agence ne lit, ne modifie, ne
supprime ni n'ajoute rien dans une autre ; un membre retiré et un visiteur ne lisent rien) et
`closed_doors.sql` (profils, agence, invitations).
